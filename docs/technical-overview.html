1. What the Application Is

A native Android reading application for the twenty-two أحزاب (litanies) of Imam Abu al-Hasan al-Shadhili. It is a typographic application first and a data application second: the difficulty is not storing the text but setting classical Arabic devotional prose so that it reads the way it does in a printed مصحف-quality edition — justified without ragged gaps, with Qur'anic quotations distinguished from the supplications that surround them.

The corpus is fixed and ships inside the binary. There is no backend, no account, no network dependency at runtime. Everything — search, bookmarks, favourites, theming — runs offline against a single in-memory dataset.

2. Feature Set

2.1 Reading

  • Mushaf typography. The whole corpus is set in KFGQPC Uthmanic Hafs, the typeface used for printed Qur'ans, at a 0.95× optical size and 2.15 line height.
  • Kashida justification. Lines are justified by elongating letters (تطويل) rather than stretching word spaces — the correct typographic behaviour for Arabic. See §5.
  • Pinch to zoom. Continuous font scaling with exponential damping; double-tap restores the default. Justification is suspended mid-gesture and recomputed on release.
  • Qur'anic distinction. Detected verses are drawn inside ornate brackets ﴿ ﴾ with per-ayah rosette numerals, and referenced by sura and verse.
  • Repetition marking. Passages the litany asks the reader to repeat appear in gold brackets, followed by the count — { ثلاثاً } — with the numeral itself picked out in gold.
  • Unified separator. Every du'a boundary uses ۞ (rub-el-hizb), replacing the asterisks the source text used.

2.2 Navigation and personalisation

  • Diacritic-insensitive search. Query and corpus are both normalised, so الرحمن matches الرَّحْمَـٰنِ. Matches are highlighted in place with circular previous/next navigation.
  • Bookmarks. Anchored by chunk index plus an exact character range, so they survive font-size changes and kashida re-justification.
  • Favourites. Up to five pinned ahzab, shown in their own section.
  • Light and dark themes with an animated 250 ms transition.

5. The Kashida Justifier

Arabic is not justified by widening spaces. It is justified by elongating the connecting strokes between letters — inserting U+0640 (tatweel). Flutter has no such facility, so the app implements it.

5.1 Algorithm

  1. Lay the paragraph out once with a TextPainter and read back the line boxes.
  2. For each line that is neither the last of its paragraph nor under the fill threshold, measure the shortfall against the column width.
  3. Enumerate legal elongation spots — positions between a forward-joining letter and a letter that accepts a join. Elongation is only valid where the script actually connects.
  4. Distribute tatweels across those spots by iterative measurement, respecting per-spot and per-word caps so no single word absorbs a whole line's slack.
  5. Emit an offset table alongside the new string so any index in the source can be mapped into the justified text.

5.2 Why the offset table matters

Bookmarks, search highlights and the Qur'an/repeat styling are all character ranges. Inserting tatweel shifts every index after the insertion point — and the number inserted changes with font size and screen width. Without KashidaText.mapIndex, a bookmark would drift every time the reader zoomed. This was the root cause of an early bug where brackets appeared to detach from the passages they enclosed.

   ▼

Layer flattening. A Qur'anic verse can sit inside a repeated passage, which can sit inside another repeat, and a repeat count may overlap both. Naively applying the ranges in order loses the inner style. The renderer therefore collects every range boundary, walks the resulting elementary intervals, and merges the styles that cover each one — so a verse keeps its mushaf face even when nested two levels deep.

7. Qur'an Detection

The Qur'anic quotations in the source were unmarked, unvocalised inconsistently, and spelled in modern orthography rather than the mushaf's رسم. An offline tool (tool/mark_quran.dart) locates them against the full text of the Qur'an and rewrites each one from the mushaf.

7.1 Method

  1. Corpus. All 6,236 ayat are fetched once and cached (tool/quran.json). Basmala prefixes on the first ayah of each sura are stripped, as are standalone pause marks.
  2. Seed index. Every 4-gram of the Qur'an is indexed by its consonantal skeleton — long vowels removed for words above three letters. This is what lets السماوات in the litany find السموت in the mushaf.
  3. Expansion. A seed grows outward while each pair of words is “the same word” under a bounded Levenshtein distance (1 for short words, 2 otherwise).
  4. Snap to ayah boundaries. The span is trimmed to the largest range of complete ayat it contains. Half-quoted verses are deliberately left as plain text.
  5. Merge and bridge. Adjacent runs of the same sura are merged; a short ayah lying between two matches is bridged if the intervening words check out.
  6. Rewrite. The matched region is replaced with the mushaf text plus per-ayah numerals, wrapped in a §Q§ marker.

7.2 Failure modes that were found and fixed

DefectEffect
Standalone waqf marks (ۖ) treated as wordsEvery passage crossing one stopped dead — the single largest cause of missed verses
Hamza-above (U+0654) not foldedWords such as بِـَٔايٰتِنا never matched
Exact-match seedingRasm/orthography differences broke matching before expansion could start
Backward-only expansionCursor failed to advance — infinite loop
Spans crossing an existing markerRewriting would have deleted the marker; such spans now shrink or are skipped
Result. Coverage rose from 32 marked passages to 131. Roughly 108 quotations remain unmarked by design: they are partial verses, or verses quoted without their narrative opening (قال), and the project's rule is that only complete ayat are presented as Qur'an.

8.1 Performance work

  • Ad SDK initialisation moved off startup. MobileAds.initialize() spins up a WebView on the Android UI thread; called from main() it stalled the intro animation. It now runs from Home's first post-frame callback.
  • Full-screen compositing layers removed. Three stacked Opacity layers and an animated full-screen radial gradient were deleted from the intro.
  • Justification suspended during gestures. The kashida pass is far too heavy to repeat per frame, so an identity transform is used while a pinch is in flight.
